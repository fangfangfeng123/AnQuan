# 自动化安全评估系统：修正后的项目文件结构

用途：对当前文件结构做职责拆分和补充，作为开始写代码前的目录设计。

本文件只描述目录结构和模块职责，不包含程序代码。

## 1. 修正原则

1. Agent 负责编排，业务执行统一放到服务层。
2. LLM 调用统一封装，避免各 Agent 各自接 OpenAI。
3. 长任务通过 worker 执行，不在 API 请求中同步跑沙箱和 Agent。
4. FastAPI 路由必须有独立请求/响应模型层。
5. Agent 与具体执行器只保留"编排调用"关系。
6. 沙箱镜像、源码快照、示例靶场、前端、数据目录从后端目录中分离。
7. 项目删除改为归档或软删除。
8. 报告、补丁、攻击链都有独立服务层，避免多个 Agent 重复实现。

作用：

### 3.5 routers

路由只负责接收 HTTP 请求、调用服务和返回响应，不直接执行业务：

- projects：创建、上传、列表、详情、归档、恢复。
- tasks：创建任务、启动、停止、详情、列表、流水线、日志。
- findings：漏洞列表、详情、证据、补丁导出、补丁采纳。
- attack_chain：攻击链图。
- reports：报告摘要、完整内容、导出、下载。
- sandbox：沙箱配置。
- llm：模型配置。
- audit_logs：审计日志。
- dashboard：概览统计。

原"删除项目"改为"归档项目"。归档后用户不可创建新任务，但历史数据仍保留。

### 3.6 services

新增服务层，业务逻辑不在路由、Agent 或扫描器中重复：

```text
app/services/
├── project_service.py
├── source_snapshot_service.py
├── task_service.py              # 含 enqueue_task()：把 taskId 推入 Redis 队列供 worker 消费
├── sandbox_service.py
├── finding_service.py
├── attack_chain_service.py
├── report_service.py
├── patch_service.py
├── audit_service.py
├── llm_config_service.py
└── dashboard_service.py         # 大盘聚合统计：总项目/运行中任务/漏洞按等级和状态分布/最近任务
```

Agent 只负责"阶段调度和决策"，具体数据库操作、文件落盘、扫描器调用由 service 完成。

Agent 与 service 的调用边界示例：

```text
CodeAuditAgent.run()
  → 决定"先跑 Semgrep 再跑污点分析"（调度决策）
  → 调用 finding_service.run_semgrep(task_id, sandbox_id)   （执行由 service 完成）
  → 调用 finding_service.run_taint_analysis(task_id, sandbox_id)
  → 调用 finding_service.create_findings(task_id, results)
  → Agent 自身不做任何 DB 操作
```

`finding_service.py` 第一版会比较重（同时管扫描执行、污点分析触发、漏洞入库），先放一个文件里，后续按需拆分。

### 3.7 workers

新增后台任务执行层：

```text
app/workers/
├── worker.py               # 从 Redis 队列消费 taskId，调用 task_executor 执行
├── task_executor.py        # 执行 orchestrator 全流程，通过 WebSocket 推送进度
└── report_pdf_worker.py    # PDF 转换放在独立 worker，避免阻塞 Agent 主流程
```

作用：

- 从 Redis 队列接收任务。
- 执行 orchestrator。
- 让 FastAPI 请求立即返回，不阻塞在长任务中。
- PDF 转换放在独立 worker 中，避免阻塞 Agent 主流程。

任务交接协议：

```text
routers/tasks.py POST /tasks/{taskId}/start
  → task_service.update_status(task_id, RUNNING)
  → task_service.enqueue_task(task_id)        # 推入 Redis 队列 "task_queue"
  → 立即返回 HTTP 200

workers/worker.py
  → while True:
      task_id = redis.brpop("task_queue")    # 阻塞等待
      task_executor.run(task_id)              # 跑 orchestrator 全流程
```

### 3.8 agents

Agent 保持原目录结构，但只负责阶段编排和决策：

- base.py：Agent 基础生命周期和统一事件输出。
- recon.py。
- code_audit.py。
- poc_verify.py。
- exploit_chain.py。
- report_gen.py。
- orchestrator.py。

ReportAgent 不重复实现报告生成，只决定何时调用 report_service。
ExploitChainAgent 不重复实现 DAG，只调用 attack_chain_service 和 dag_builder。

### 3.9 sandbox

`app/sandbox/manager.py` 只负责容器操作，不保存镜像：

- 创建容器。
- 只读挂载源码。
- 设置网络、资源和能力限制。
- 执行命令。
- 回收日志。
- 销毁容器。

具体镜像文件放在项目根目录 `sandbox-images/`。

### 3.10 scanners 与 taint

建议拆成两个目录：

- `scanners/`：工具适配器。
- `taint/`：污点分析引擎。

示例：

```text
app/scanners/
├── semgrep.py
├── bandit.py
├── codeql.py
├── joern.py
├── dependency_check.py
└── base.py

app/taint/
├── source.py           # Source 规则定义（request.args.get / request.json 等）
├── sink.py             # Sink 规则定义（cursor.execute / os.system / subprocess.call 等）
├── sanitizer.py        # Sanitizer 规则定义（escape / parameterized query 等）
├── engine.py           # 污点传播引擎（AST 遍历 + 数据流追踪）
├── result.py           # TaintResult 输出模型
└── facade.py           # 统一入口，CodeAuditAgent 只调用 taint_facade.analyze(source_path)
```

第一版可以只实现 Semgrep，但目录应预留 CodeQL、Joern 和依赖扫描能力。

`taint/facade.py` 作为统一入口，Agent 不直接 import engine，而是调用 facade 的 analyze 方法，内部协调 source/sink/sanitizer 三类规则和 engine 执行。

### 3.11 poc

`poc/` 拆成以下职责：

- `poc/executor.py`：执行探针。
- `poc/payloads.py`：探针模板。
- `poc/verifier.py`：判断预期特征是否匹配。

不要把"执行、模板、判断结果"全部塞进一个文件。

### 3.12 exploit

`exploit/dag_builder.py` 负责 DAG 构建：

- 读取 verified 漏洞。
- 分析前置条件、后置能力和权限变化。
- 检测环路。
- 输出节点、边和最终影响。

Agent 只调用该服务。

### 3.13 reports 与 report-templates

```text
app/reports/
├── generator.py
└── exporter.py
```

职责：

- generator：组装报告章节。
- exporter：转换 Markdown、HTML、PDF。

模板放在 `backend/report-templates/`，包含 Markdown 和 HTML 模板。

### 3.14 patches

`patches/` 需要拆分成生成、校验、持久化：

```text
app/patches/
├── generator.py
├── validator.py
└── repository.py
```

- generator：构造 LLM 上下文并生成建议。
- validator：执行语法、编译或安全回归校验。
- repository：保存 Diff、校验结果和采纳状态。

### 3.15 llm

新增统一 LLM 层：

```text
app/llm/
├── base.py            # 基类：含 token 计数器 + 预算超限抛 LlmBudgetExceeded
├── factory.py         # 工厂模式入口，get_client(mode) 返回对应客户端
├── openai_client.py
├── ollama_client.py
└── demo_client.py
```

所有 Agent、报告和补丁模块都通过 LLM 层调用模型，不直接写死 OpenAI 地址或 Key。

`base.py` 维护一个 `remaining_tokens` 计数器，每次调用前检查预算，超限则抛出 `LlmBudgetExceeded` 异常。编排引擎启动时从 `llm_config` 读取预算上限传入。

## 9. 目录修正对照

| 原结构问题 | 修正方式 |
|---|---|
| Agent 和报告生成职责重复 | 增加 services，Agent 只负责编排 |
| 缺少 LLM 统一封装 | 增加 app/llm，base.py 含 token 预算控制 |
| 缺少 API 请求响应模型 | 增加 app/schemas，common.py 定义通用响应包装 |
| 缺少后台任务执行 | 增加 app/workers，含 Redis 队列交接协议 |
| 缺少沙箱镜像 | 增加 sandbox-images |
| 只支持 Semgrep 和 Bandit | 预留 CodeQL、Joern、Dependency-Check |
| 项目删除逻辑风险 | 路由改为归档、恢复和软删除 |
| 没有总代码行数 | SourceSnapshot 增加 lineCount |
| 没有总体风险枚举 | enums 增加 OverallRisk |
| 没有前端、靶场、数据目录 | 顶层增加 frontend、targets、data |
| Docker 只存在后端目录 | 顶层拆分 dev、demo、prod Compose |
| 缺少大盘聚合服务 | services 增加 dashboard_service.py |
| 污点分析缺统一入口 | taint 增加 facade.py 作为 Agent 调用入口 |
| LLM 无 token 预算控制 | llm/base.py 维护 remaining_tokens 计数器 |
| workers 与 API 缺交接协议 | task_service 增加 enqueue_task，worker 从 Redis 消费 |
